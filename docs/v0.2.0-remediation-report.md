# Recon MCP v0.2.0 audit remediation

## Executive summary

The branch now connects only to validated numeric addresses while retaining the authorized HTTP and TLS hostname. Campaign operations use a storage-wide Linux lock, and the integrity verifier detects an interrupted artifact and sidecar update. Scope diagnostics redact rejected inputs, preserve unknown eligibility, and report structured errors. Passive discovery rechecks policy after provider I/O and before publishing results.

This document records the first remediation pass. Its local verification covered the original reproductions. The subsequent independent verdict was **APPROVED WITH CONDITIONS**, with nested userinfo residuals in FINDING-03 and FINDING-04. See the [final qualification report](v0.2.0-final-qualification-report.md) for the current evidence and pending review.

## Reproduction evidence

1. **FINDING-01.** With the original HTTPX wiring and both DNS and the socket mocked, the approved hostname was resolved twice. The first result was a public address. The mock socket received the second result, loopback. The replacement transport test uses the same two-answer setup and records one lookup followed by a connection to the first address.
2. **FINDING-02.** Running the original graph read-modify-write sequence without the new surrounding lock let two threads load the same graph snapshot. Both returned success and the final graph contained only one new node. The former artifact writer published bytes before its sidecar, leaving an observable intermediate state. The termination test now stops a separate writer at that boundary, verifies that the marker is reported, and checks recovery by explicit retry.
3. **FINDING-03.** Calling `explain_scope_decision` with a synthetic rejected credential-bearing URL exposed the username and credential marker through the explanation fallback. The regression serializes the explanation, resolver, batch, parent recommendation, and nested audit record. A separate STDIO case supplies a credential marker inside an invalid argument type to exercise the SDK error boundary.
4. **FINDING-04.** A query using a semicolon before a sensitive assignment was authorized by the original single-convention query check. The new regressions cover decoded separators, nested percent encoding, embedded assignments, malformed encoding, and requests that must stop before DNS.
5. **FINDING-05.** The previous passive path loaded its policy before provider I/O, wrote the raw names cache, and classified candidates against the original policy. Its two-way classifier labeled a regex match as exact. The regressions change policy inside the provider transport mock and require no cache or results publication. A synthetic Burp policy and malformed and credential-like provider values exercise candidate rejection and the separate regex classification.
6. **FINDING-06.** A malformed policy raised `ScopeError` through `get_scope_map` instead of producing a structured result. A manual host entry also returned bounty eligibility as true. Regressions assert structured fail-closed results and verify that matching manual URLs keep eligibility unknown and execution flags false.
7. **FINDING-07.** The original README inventory contained 61 tool signatures despite the server registering 67. It also described independent connection-time resolution and omitted the new policy components from the layout. The STDIO regression extracts the documented names and compares them with actual registrations.

## Architecture and compatibility decisions

- **Destination validation.** `http_fetch.py` supplies the currently authorized origin and checked DNS addresses to an HTTPX `BaseTransport`. The transport uses HTTPCore's public `ConnectionPool`, `NetworkBackend`, and `NetworkStream` interfaces. It creates a pool per request with reuse, proxy lookup, and internal retry disabled. A bounded numeric-socket connector checks the reported peer. The original authority stays in HTTP, and the TLS stream enforces hostname and Certifi chain verification. The tests check the TLS context and server name at the mocked socket boundary and exercise certificate-validation failure handling.
- **Campaign synchronization.** One private lock lives beside the active and archived roots, outside any campaign directory. Same-thread nesting is reentrant and uses one storage transaction. Separate threads and processes contend through Linux `flock` with a two-second timeout. Forked children close inherited lock descriptors. The code checks the lock's ownership, mode, type, link count, and mount. Supported local mount types include Btrfs, ext2/3/4, tmpfs, and XFS. Missing required locking support returns a structured failure.
- **History and artifact publication.** Audit and negative-result appends open paths by directory descriptor, reject links and non-regular files, synchronize completed records, and recover a bounded unterminated last record. Artifact writers synchronize a marker before publishing a content and sidecar pair. Readers hold the same lock. A retained marker reports an interrupted publication and an explicit retry can replace the pair. Within one operation, other files such as graph and report outputs remain individually atomic where previously supported. No database-style transaction was added.
- **Scope and passive discovery.** Redaction and credential detection share bounded query inspection. SDK-wrapped validation errors return generic MCP tool errors without echoing arguments. Scope-policy failures retain reason codes. The legacy BugMap label recommendation still consumes the local host/asset metadata contract. An external BugMap installation was unavailable for qualification. The interoperability migration and all flags are documented in the [scope guide](scope-authorization.md#interoperability-flags). Passive discovery uses current policy between provider I/O, classification, optional DNS, and persistence. Optional DNS runs in the owning storage transaction, one candidate at a time, to avoid cross-thread lock reentry.
- **Dependencies.** The package now requires HTTPX 0.29.x, HTTPCore 1.0.9 through 1.0.x, and Certifi for the TLS trust store. Runtime qualification used the versions above. The existing MCP 1.x constraint remains in place. The supported Burp regex subset is unchanged and covered by the [synthetic export](../config/burp-scope.example.json).
