# Recon MCP 0.2.0

Recon MCP 0.2.0 evaluates complete URLs against a reviewed local policy before a scoped network operation can proceed. Supported policy sources are manual rules, one selected local HackerOne snapshot, and a documented subset of Burp Advanced Scope. Six offline diagnostics validate and compare policies, explain URL decisions, and report capabilities. The MCP server exposes 67 tools.

- The HTTP transport connects to a validated numeric endpoint and preserves the original hostname for TLS verification.
- Campaign operations use a current policy binding. Coordinated writes and interruption detection protect campaign evidence on supported local Linux filesystems.
- URL checks deny supported sensitive and ambiguous credential representations before DNS. Diagnostics and metadata redact those representations.

Independent security qualification reported all seven findings closed and 601 tests passed with zero failures or skips. The verified environment was Fedora Linux 45 x86_64 with GIL-enabled CPython 3.15.2, MCP 1.30.0, HTTPX 0.29.0, and HTTPCore 1.0.9. Fedora installations use a versioned runtime with private policy and evidence paths that stay fixed across compatible upgrades. Follow the guide for verified dependencies, offline client checks, rollback, and migration. [Fedora installation and release verification](https://github.com/tobiasGuta/recon-mcp/blob/v0.2.0/docs/v0.2.0-release-preparation.md)

Campaign storage requires a supported local Linux mount. The documented Burp subset, socket-level transport checks, and bounded credential inspection define the release's qualification limits. Keep raw evidence private and review the source program rules before authorizing a URL. [Scope and authorization guide](https://github.com/tobiasGuta/recon-mcp/blob/v0.2.0/docs/scope-authorization.md)
